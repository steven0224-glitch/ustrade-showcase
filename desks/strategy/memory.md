### 2026-07-07 [confirmed]

코드 감사와 전략 감사는 다른 작업이다. 적대적 코드 감사 4라운드를 통과해 수렴한
시스템에서도 **구조적 마이너스 기대값**이 남아 있었다. 코드는 전부 옳았고 상태머신
설계는 최고 평가를 받았다. 틀린 것은 설정값의 경제학이었다.

정확성 감사는 "계산이 맞나"를 보지, "그 계산으로 돈이 벌리나"를 보지 않는다.
왕복 거래비용을 코드 상수에서 직접 산출하니 0.35% (수수료 0.1%×2 + 슬리피지 0.05%
+ 반스프레드 0.025% 양방향). 이 비용 기하와 페르소나별 기대 이익폭을 대조해야
-EV 설정이 드러난다.

_근거: lessons/2026-07-07-strategy-audit-cost-geometry.md (텔레그램_시그널_알리미 프로젝트)_

**규칙: 전략을 승인하기 전에 왕복 거래비용을 코드 상수에서 직접 산출하고, 평균 기대 이익폭과 나란히 적어라. 비용이 이익폭의 1/3을 넘으면 기각한다.**

### 2026-07-07 [hazard]

임계 기반 경보·조건을 새로 설계할 때, **발동 가능한 입력이 실제로 존재하는지 식으로
먼저 검산해야 한다.** 비교 양변이 같은 시점 데이터에서 유도되면 퇴화(항등 간격)가
숨는다. 실제 사례: `atr_stop = 오늘 종가 − 2.5×ATR` 에 대한 "현재가 근접" 판정은
현재가가 정의상 항상 스톱 위 2.5 ATR 이라 영원히 발동하지 않는다. 스펙 문구를
그대로 구현했으면 조용히 죽은 경보가 배포됐을 것이다.

양변이 독립 소스(진입 시점 고정가 vs 현재가)면 이 함정은 없다.

_근거: lessons/2026-07-07-stop-proximity-anchor-math.md_

**규칙: 새 조건식은 구현 전에 "이 판정이 발동하는 입력이 존재하는가"를 대수적으로 검산한다.**
