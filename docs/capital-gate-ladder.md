## 불변식 (모든 단 공통)

1. **손실 상한 = cash_cap.** 각 단의 최악 손실은 "그 단에 넣은 돈 전액"으로 가정한다
   (정상 가드 작동 시 ≈ cap×20%(누적DD 한도)+갭이지만, 결함·갭 시나리오에선 cap 전액).
   → **cap 은 "전액 잃어도 계획이 안 바뀌는 금액"으로만 설정.**
2. 승격 조건은 **승격 전에 숫자로 등록** — 단 진행 중 조건 변경 = 그 단 시계 리셋.
3. 강등은 즉시, 승격은 시계 만료 후에만 (비대칭 — 안전측).
4. 킬스위치 namespace 분리(`killswitch.toss.json` ↔ paper) 상태로 운용 — paper 잔재 스케일
   혼입 오트립 방지는 guardrail.py 에 실장돼 있음(스케일 급변 재seed). paper* reset 이 전역
   HALT 를 못 지우는 것도 실장 확인.
5. 본인 개입(수동 주문·수동 청산·스케줄 중단)은 **금지가 아니라 기록 의무** — 매 개입을

## 강등 규칙 (전 단 공통 — 즉시 적용)

| 사건 | 조치 |
|---|---|
| 손실성 트립 (daily_loss / total_drawdown) | 거래 정지 상태에서 원인 분류 → 시장성(전략 정상 작동) = **해당 단 시계 리셋** 후 재개 / 시스템성 = 아래 행 |
| 구조 결함 (bad_* · position_bound · 슬리브 위반 · error 누적) | **L1 로 강등** — 수정 + 리허설 재통과 후 L2 부터 재승격 |
| total_drawdown 트립이 2개 단에서 반복 | **실험 중단** — L0 재검토 (엣지 가정 자체 재심) |
| 기록 없는 개입 발견 | 해당 단 시계 리셋 + interventions.md 소급 기록 |
| 증액 직후 1주 내 손실성 트립 | 직전 단으로 cap 복귀 (증액 재도전은 시계 재충족 후) |

**사후 변경 금지**: 단 진행 중 그 단의 승격 조건·cap 을 바꾸면 그 단 시계 리셋. 완화 방향
변경은 리셋 + 사유 1줄 기록. (paper-trading-dod §B 와 동일 규율.)
